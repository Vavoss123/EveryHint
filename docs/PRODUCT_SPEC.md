## P10 current product contract

Calendar and People are working dashboard destinations. The contextual workspace starts locked; unlocking provides encrypted local cache/People/memory access without connecting a service or granting AI. Google Desktop client IDs are configured in Settings. Calendar and Contacts have separate explicit read-only connections, independently of ChatGPT. Public Google distribution approval is not claimed. See [setup and architecture](ARCHITECTURE.md#p10-google-setup-and-distribution).

Calendar supports up to five selected calendars, a complete paginated past-7/future-90-day window (at most 1,000 events), recurrence instances/cancellations, supplied attendee/location/link information, dates/time zones/DST and day/seven-day/upcoming/search views. Manual refresh is default; chosen background refresh runs about every 15 minutes with bounded backoff. This is **not Calendar incremental sync**. Local reminders are disabled or 5/10/15/30 minutes before timed events, with persistent at-most-once receipts and at most two minutes of catch-up. The app must be running. A notification opens preparation only; a meeting link requires deliberate opening. All-day reminders are omitted. Calendar timing can suggest preparation/capture selection; conferencing-app/process inspection is deferred.

People offers optional fields, manual CRUD/search/notes, explicit saved-meeting links and outstanding actions. User facts remain separate from minimal Google snapshots with retrieval time. Contacts requires its own read-only permission, explicit search/selected import, and a second acknowledgement for manual whole-address-book sync (at most 1,000 contacts). Stable paged sync tokens, seven-day expiry/full reset and provider deletions are handled. Manual facts/notes survive imported snapshot removal. Exact matching requires a source-verified or explicitly user-confirmed email; aliases, names and voices are not identity evidence. External professional research remains deferred because no approved provider is configured.

Memory is independently off by default. Explicit rebuild selects ended/interrupted saved P8 meetings and enabled P9 documents. Literal notes, explicit supported decisions/actions/topics/follow-ups and document passages become structured encrypted records with source/revision/ref/quote/time/person/topic/status/authorship/review. Extracted records start pending. Only approved records with available current sources can enter AI context. The local review UI supports edits, individual/all deletion, manual notes, person/meeting filters and exclusions, retention (30/90/365 days or until deletion) and rebuild. At most 1,000 records are retained. P9 keyword ranking adds topic/person/meeting, review/evidence and recency signals; semantic retrieval is absent. Changed/deleted sources invalidate pending remote permission and remove dependent records while stores are available. Locked-source derivatives cannot be sent; deferred cleanup and erasure limits are documented in ARCHITECTURE.

Prepare an event using selected participant facts, up to eight approved memories, three ended saved meetings and optional active-mode knowledge. Preview exact bounded excerpts and remove items before the fresh remote acknowledgement. The same AssistantController/official ChatGPT Responses path preserves `store:false`, `stream:true`, model discovery, no tools and no paid fallback. A brief distinguishes supplied facts from suggested talking points/questions and states missing objectives/background. Source citations are supplied references, not semantic proof. Drafts are ephemeral; saving requires a chosen encrypted retention policy (7/30/90 days) plus an explicit save acknowledgement, at most 30 briefs. Copy, exclusive-file plaintext export and meeting links are deliberate actions. Regeneration prepares a new review. Calendar/P8/recurring associations never overwrite independent saved titles/notes.

Ordinary answers can explicitly select P10 context too. Workspace answers do not enter automatic follow-up history; select sources again for another request. Live context requires staging an exact bounded selection, reviewing its source texts, opting in to that selection and separately authorising remote sharing for the current Live session. P7 source/account/mode/session guards, spoken-question trigger, cooldown and attempt cap remain. No Google connection, memory preference, reminder, calendar hint or source stage enables capture, joins, saving or inference.


## P9 personalisation contract

General, Coding, Interview, Sales and Meeting plus legacy Conversation share one provider-independent typed mode system. Users can create/edit/duplicate/rename/delete custom modes, reset protected built-ins, restrict context/actions, associate documents/templates and test through the existing frozen review/acknowledgement/Ask. Mode changes cancel old requests and sharing grants without acquiring capture or starting inference. Existing General/Code/Conversation preset inputs migrate, and prior saved settings remain compatible.

The dashboard has functional Modes and Knowledge pages; Settings holds global/default mode, response-language and template controls. A native picker imports PDF, DOCX, UTF-8 TXT and Markdown locally through a disposable bounded parser worker. Limits are 8 MiB input, 400k extracted characters, 200 PDF pages, 500 sections/document and 100 documents/profile. AES-GCM content/metadata use P8 cipher/key/profile architecture with a distinct native credential namespace and worker SQLite. Only extracted text/metadata are copied; originals are never modified/deleted. No OCR, cloud conversion/upload, paid embeddings or persistent plaintext index exists.

Retrieval ranks enabled, explicitly selected active-mode documents locally (at most ten); up to four deduplicated excerpts/4,800 text characters fit within the existing request budget. Exact names/headings/pages where real/excerpts/ref IDs appear before manual sharing and on answers. Citations identify supplied references and do not prove semantic support; unavailable refs are warned. Document text is untrusted and cannot grant permissions. Live knowledge defaults off and requires separately selected source IDs, retrieval enabled and remote-sharing permission within the existing expiring cooldown/cap/session grant. Uploading never triggers inference.

Response language is a global best-effort preference with per-mode override, independent of speech. tiny.en/base.en remain honestly English-only; multilingual models are deferred and no download is automatic. Four built-in note templates and a custom ordered section editor reuse the P8 strict evidence schema. Template choice is frozen in review and saved snapshots drive display/export. Drafts require Apply, manual notes stay intact and prior summary versions are preserved under bounded retention. Full architecture, format limits and precedence: [P9 decision](DECISIONS/P9-personalisation.md). Exact evidence/manual gaps: [TESTING.md](TESTING.md).

## P8 meeting contract

Temporary sessions remain the default: P3 final/provisional text stays in bounded memory and opening Meetings does not open a database. Local-history preferences are separate per installation/selected signed-in registration (signed-out history is separate). Enable saving and acknowledge the selected 7/30/90-day or indefinite retention policy, then explicitly save a current/retained session. Optional auto-save is off by default and covers future authorised audio sessions only; it never starts capture. Raw audio/screenshots are never persisted. Retention is measured from last modification and applied when unlocked or explicitly changed; active recordings are excluded until ended. Disabling saving keeps existing records subject to the chosen retention/deletion policy.

Saved meetings contain real editable title/times/duration/status, separate capture runs/source metadata, final segment/session IDs and timestamps, manual notes, optional reviewed summaries, decisions/actions, tags and modification/revision metadata. Finals deduplicate by meeting/session/segment, retaining mic/system provenance. System audio does not identify people; only explicitly supplied speaker labels are saved. Resume arms one fresh capture run under the selected saved meeting and opens normal consent; reopening never acquires a source or restores remote permission.

SQLite runs in a dedicated worker. Sensitive fields are AES-256-GCM authenticated ciphertext before SQL receives them; keys live in a distinct Windows Credential Manager entry. UUID/status/timing/count/revision/expiry metadata and file size remain visible. Versioned transactional migrations, authenticated key checks, corruption preservation, interrupted-write recovery and application-level deletion are tested. Missing keys with existing data fail closed without replacement. This is a same-OS-user boundary, not protection against malware running as that user, paging/crash dumps or guaranteed SSD erasure. See [P8 design](DECISIONS/P8-meetings.md) for actual boundaries.

History lists 25 records/page; full transcripts load 100/page (20,000 segments and 100 capture runs per meeting; 10,000 meetings). Explicit unlocked search decrypts bounded work in the worker: at most 25 meetings, 1,000 segments or about 4 million text characters per continuation. It searches titles/tags/manual notes/summary/decisions/actions/transcripts and user speaker labels. Date filters and newest/oldest order use start time, or creation time for manual drafts. Exact tags and useful escaped snippets are supported. Cursors and search state are memory-only, expire on deletion/retention/restart and never create a plaintext disk index. Full-transcript search returns up to 30 matches per 1,000 scanned segments; Continue searches the rest.

Overview/Transcript/Notes/AI tabs provide evidence references, optimistic save/revert, explicit user corrections and manual-vs-AI provenance. Unsaved edits survive navigation; conflicting saves fail visibly. Manual notes are never replaced by generation; selected manually edited generated sections need a separate overwrite acknowledgement. A reload control allows inspecting the latest saved version after reverting unsaved edits.

Meeting AI selects one temporary retained session or up to three saved meetings, independently chosen mic/system/user-note sources and up to 100 explicit segment references. Context is bounded to 12,000 excerpt-text characters and 14,500 serialized excerpt characters. It is untrusted reference text, shown with exact account/model/prompt/excerpts before a new transfer acknowledgement. All requests reuse the official ChatGPT-plan provider and stream/terminal checks, with no tools, screenshots/raw audio, whole-history upload, paid fallback or ordinary-live-history contamination. Summaries use exact selected quotes/refs and explicit uncertainty; absent owners/deadlines stay Unassigned/Not specified. Quote validation is not semantic fact verification: review remains necessary. Results stay unsaved until Apply. Selected-meeting QA, recap, follow-up and action summaries share the same gate.

Automatic End notes are independently off by default. One acknowledged grant binds the current capture run/account/model/saved association, chosen transcript sources, 1–60-minute expiry and one attempt. Only deliberate End qualifies; resumed meetings include only that newly authorised run. Pause/Stop/source/account/model/setting/expiry/lifecycle changes revoke; empty text/offline/rate failures never retry or fall back. Root status, Cancel, native title and tray disclose saving/remote notes, including while hidden. General Stop stays an emergency revoke rather than a post-summary trigger.

Export uses a native save dialog and separate plaintext acknowledgement: final transcript TXT, Markdown notes, full structured JSON or readable summary TXT. New files only; existing files are preserved. Transcript/JSON exports stream in bounded pages, cancel on meeting/profile changes, and remove their own incomplete new file when possible; failure to remove is reported. Clipboard offers summary/actions/transcript (one-million-character transcript cap). Exports/clipboard/history in other applications may be unencrypted or synced independently, and local deletion cannot remove them or recall provider text. Follow-up email remains editable with blank recipients; a separate exact-draft approval opens only a validated bounded mailto link (1,800 encoded characters, up to five explicit recipients, no truncation). Long drafts can be copied. No send action, hosted share links or Gmail connector exists; those are deferred.

## P6 manual Assist contract

Get Answer opens a frozen transmission review. A question is optional when selected, available screen/transcript/previous-exchange context exists. General Assist, Code Assist and Conversation Assist are fixed response presets beneath immutable answer-only safety instructions. Empty context is rejected. This explicit Manual contract is retained alongside the separate P7 modes below. P9 extends these legacy presets with the shared custom-mode system.

Screen inclusion obtains an on-demand frame from the current consented, ACTIVE source through the existing serial capture service. No arbitrary renderer image/path/source is accepted. Native JPEG snapshots fit within 1600 by 900 pixels, with a selected byte cap (default 1.5 MB, maximum 4 MB). Main validates dimensions, data URL, freshness within 10 seconds and at most one second of future clock skew. Source name, timestamp and exact image are shown in the review; unknown image capability, paused/stopped/unavailable capture, stale/oversized images and already-submitted image hashes fail explicitly. Review/submission expires within two minutes of the image timestamp. For a full-screen source, pause to inspect its frozen review image, or select an external application window for a live preview. EveryHint's own windows are excluded; there is no evasion feature. A paused frozen review remains independently reviewable until expiry; Stop clears it.

Microphone and system transcripts are independently optional. Windows are 30, 60, 180 or 300 seconds. Only consented, current-session final utterances wholly within the window are eligible. Source/time labels and chronological order survive trimming; overlapping duplicate final text is suppressed per source. System audio identifies a capture source, not a known person. Raw audio never enters requests. Users may remove individual excerpts, previous exchanges or the image from a frozen review. Each removal creates a new review ID and resets approval; removed utterance IDs stay excluded for that conversation. Settings, diagnostics and credentials are not context inputs.

After inspecting the exact prompt/image, users must acknowledge this specific remote transfer, then Ask. Selected information goes to OpenAI for ChatGPT plan inference. The existing public Responses transport uses `input_text` plus an optional JPEG data URL `input_image`, `store:false`, `stream:true`, `tools:[]`, `tool_choice:"none"` and a frozen account/model. No server-side conversation ID, previous-response state, API-key fallback, Files API or tool executor is used. Claude remains default-off and requires its separately permitted API configuration and billing opt-in.

Follow-ups explicitly review selected bounded question/answer history (four pairs / 12,000 characters, 15-minute idle expiry); screenshots and transcripts must be selected again. Clear context cancels execution and clears in-memory history/review; account/provider/capture-session changes isolate conversations. Regenerate prepares the latest question and earlier exchanges for a new review without reattaching previous images/transcripts or feeding the answer being replaced back into history. A context-only answer may need a question or freshly selected context before another request. New manual approval is always required; Live uses its own bounded, independently acknowledged grant. Late/cancelled requests cannot update a newer session.

Safe React-rendered Markdown supports paragraphs, headings, lists, emphasis, inline/fenced code, language labels, per-code copy and simple tables, including incomplete streaming fences. HTML, links and images remain inert text; there is no code execution or syntax-colour claim. Compact mode shows provider/latest response/Get Answer/Expand; capture Pause/Stop and remote Cancel remain accessible.

Settings configure global Assist (default Ctrl+Alt+A) and Clear context (Ctrl+Alt+Shift+C). Chords are validated against each other and fixed Show/hide/Pause/Stop controls; OS conflicts are reported with UI/tray fallbacks. Assist opens/focuses the composer and prepares selected context for review, never inference. Local Ctrl+Enter only opens/focuses while EveryHint is focused. Physical hotkey and P5 Windows checks remain manual acceptance, separate from simulated-event tests. Live image/follow-up evidence is recorded in [TESTING.md](TESTING.md); mocks do not establish image reasoning.

## Context and consent model

**Manual (implemented):** users explicitly authorise local capture sources and transcription, independently select final mic/system text, screenshot and bounded question/answer history, review the frozen payload/model, and acknowledge each remote Ask. Raw audio stays local. A text-only question needs no capture. Source consent is not remote-sharing consent. Capture continues when hidden only if already explicitly active; tray/status and emergency controls explain this.

**Auto-Hint (implemented):** selected consented final microphone/system transcripts and stable screen changes are analysed locally. At most three ranked suggestions can be accepted into the shared frozen review, dismissed, suppressed as similar or allowed to expire. Acceptance never submits; remote Ask still needs review/acknowledgement. Screen changes alone only propose reviewing current context.

**Live Assist (implemented):** a separate acknowledged grant binds the current ChatGPT account/model, assistant/capture session and epoch, exact selected screen/window, transcript/image/history categories, trigger and limits. Defaults: 30 minutes, minimum 30 seconds between attempts, maximum 20 attempts. Limits are attempt counts, not monetary estimates; failed/uncertain attempts count. Only fresh high-confidence final spoken questions from shared sources trigger automatic Get Answer. One active request and at most one fresh pending candidate are allowed. Manual reviews have priority. No Claude automatic requests, retries or paid fallback exist. P7 operating mode and sharing grant never persist. Capture Pause/Stop, Pause Live, cancellation, expiry, source/account/model/provider/intelligence-setting changes, Clear, lock/suspend/reload/crash/quit revoke sharing; Resume does not restore it. Root status, native title and tray show remote-enabled state even between requests or while the overlay is hidden. The existing five-minute model catalog may pause a longer grant early; refresh, reselect and authorise explicitly.

Retain current privacy bounds: no automatic screenshot/ordinary-AI-history persistence, separately opted-in P8 final-text persistence only, local Whisper, selected-source/context validation in main, two-minute one-use review, 90-second inference deadline, 32,000-character responses, bounded QA memory/15-minute expiry, stale request/session guards and no automatic API/provider fallback. P8 storage/retention/access/deletion is defined above; future mobile synchronisation remains out of scope and needs its own design.

## P7 local algorithms, actions and bounds

English interrogative/help rules do not require punctuation. They suppress reported/rhetorical/unrelated/incomplete cues and provisional/repeated/cross-source echoes, then combine relevance with a heuristic score (default 0.85; configurable 0.85–0.99, not a calibrated probability). Context uses nearby source-labelled final excerpts within 30 seconds and an optional current selected screen; it never identifies a person from a voice/source. A distinct authored classifier fixture comparison did not justify adding a model or dependency. Multilingual models and diarisation remain unimplemented.

Encoded screen hashes avoid repeated decoding. Changed images are reduced to 32×18 intensity samples; substantial mean/fractional differences must stabilise over at least 600 ms. No continuous images are uploaded. A screen change is not evidence of a question/error and never triggers remote inference alone. Windows OCR was evaluated but not added to this unpackaged prototype. Source exclusion covers a selected window/monitor handle, not selective masking of other apps inside a monitor image.

Seven typed actions use fixed instructions and the existing builder: Get Answer, What Should I Say Next, Suggest Follow-up Questions, Fact Check, Recap, Who Am I Talking To and Dynamic Suggestion. Fact Check remains visibly **unverified/context-only** without external retrieval. Recap uses only the selected retained window, not full-session P8 notes. Who returns user-provided participant information or unknown locally; there is no research/calendar/biometric lookup. Other actions prepare explicit reviews. Local event retention defaults to five minutes (1–15); bounds include 100 events, 20 questions, 100/12,000-character recent excerpts, 2,000 seen IDs and three suggestions. Question suggestions expire within 90 seconds and remaining retained time. Live rejects stale triggers older than 30 seconds and pre-authorisation questions. Immutable provider instructions treat all captured content as untrusted reference data. Removed transcript IDs cannot become automatic questions.

See [architecture](ARCHITECTURE.md), [design and checkpoint measurements](DECISIONS/P7-intelligence.md) and [verification/manual gates](TESTING.md).

## Provider and execution policy

Use permitted official authentication. EveryHint owns its registered ChatGPT connection; no shared Codex token, browser cookie or reverse-engineered endpoint is imported. Credentials stay outside React in native OS storage. Catalog visibility is advisory until inference completes. Screenshots require explicit image metadata; unknown support blocks them. ChatGPT plan usage limits remain provider/account-specific.

Claude subscription authentication remains conditional on Anthropic approval for distribution. Its API path requires a locally configured key and explicit, separately billed session opt-in; P7 makes no paid request. Future release eligibility is not established merely by the successful private ChatGPT test.

Captured content is untrusted reference material, never authority. Providers cannot execute arbitrary shell commands, change files, install packages or control the computer. Future factual research must use an explicitly authorised capability with source/uncertainty disclosure. Sharing, email and calendar writes require independent permission/review; P10 provides separately consented read-only Google Calendar/Contacts without granting writes or AI sharing. Enterprise integrations/administration are permanently removed.
