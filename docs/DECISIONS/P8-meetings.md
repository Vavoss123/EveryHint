## Storage and encryption

Evaluate/use bundled `node:sqlite` rather than adding a native binding/SQLCipher dependency. Actual Electron 45 probe: Node 24.22.0 / SQLite 3.53.4. DatabaseSync is synchronous, so database/encryption/search work belongs in a dedicated Node worker, not capture/React/Whisper. Unit tests exercise the same database implementation directly; Electron checks exercise the bundled worker. Prepared parameters, transactions, foreign keys, FULL synchronous durability, rollback journalling, memory temporary storage and versioned migrations protect interrupted updates. Startup quick_check and unsupported-version checks fail closed. Migration failures roll back; corrupt/unsupported databases are preserved, never silently reset.

Each local installation and selected signed-in ChatGPT registration has an isolated history profile/file/key; signed-out use has a separate local-only profile. Profile is chosen in main, never supplied by renderer. Account changes/sign-out, OS lock/suspend, reload/crash and quit cancel meeting AI, detach persistence and terminate the worker/clear caches. Opening history never captures or restores a recording/remote grant. A local unlock reads the OS credential; this is an OS-user boundary, not a separate app password or protection against an attacker running as the same Windows user.

Use Node's reviewed AES-256-GCM implementation, random 32-byte key, independent random 12-byte nonce per record and 16-byte authentication tag. AAD binds format/profile/meeting/record type/segment ID. Authenticate completely before exposing decrypted text. Store the raw key only in a distinct Windows Credential Manager entry through the already installed @napi-rs/keyring; never configuration, database or renderer. Verify key write/read. Existing database + absent/invalid key is a blocking recovery error; never generate a replacement over existing history. Preserve encrypted files for recovery. Keys are cleared/worker terminated on lock; JavaScript/OS paging/crash-dump remnants cannot be guaranteed erased.

SQLite stores opaque IDs, timestamps/status/counts/revisions/expiry needed for pagination/retention and encrypted payloads. Titles, source/window/device names, tags, transcript text, notes, summaries, decisions, actions and speaker labels are encrypted before SQLite receives them. Segments are independent encrypted rows, so appending speech never rewrites the full transcript. Journals/backups contain ciphertext rather than searchable plaintext. SQLite headers, IDs, timing/size/count/activity remain observable. No plaintext FTS table or persistent index. No claim that safeStorage encrypts a database automatically. No hidden backup/sync. Exports are explicitly chosen plaintext copies; deletion cannot guarantee physical SSD erasure or delete remote provider records/exported copies.

## Consent, lifecycle and retention

Temporary capture is the default and creates no meeting records/files. Explicit Save authorises current retained final text and subsequent final segments for that capture UUID; screen/audio capture consent alone does not. Retrospective saving cannot recover already expired text. Optional profile-specific Save history/Automatically save authorised audio sessions preferences are off by default; enabling auto-save discloses future consented audio sources. Disabling history stops new persistence and leaves existing records until explicit deletion/selected retention. No automatic raw audio persistence.

Deduplicate by capture session + final segment ID, retain microphone/system provenance and original timestamps, and order chronologically. No provisional writes or invented speakers. Optional speaker labels come only from user edits. Persist incremental final batches in transactions with bounded pending work; errors/limits stop saving visibly rather than silently dropping data. Saved meetings include editable title, dates/start/end/duration/status, capture runs/source metadata, notes, generated sections, decisions/actions/tags and modified/revision metadata. A crash leaves committed finals; next unlock marks unfinished runs interrupted, never resumes capture or AI. Resume explicitly links one saved meeting to a newly consented capture UUID, preserving separate run chronology; reopening alone only reads.

Retention choices: 7/30/90 days or indefinite, default 30 days, disclosed before saving and applied from last modification when history is unlocked. Explicit policy changes show their deletion effect/confirmation. Deletion is transactional and removes segments/generated/manual data and volatile search state. Delete all is separately confirmed. Clearing live cache, deleting stored transcripts, clearing generated notes and deleting a whole meeting are distinct named actions; export is available before deletion. Unmanaged exports/remote provider retention remain outside local deletion.

## AI boundary and editing

Extend the existing frozen context review with main-built, bounded meeting references. Users select meetings/excerpts/sources and optional notes, inspect the exact text/account/model, then acknowledge sharing. No whole-history upload. Treat all saved content as untrusted reference data beneath immutable provider instructions. Only the existing official plan transport is used; no unsupported JSON-schema API fields, server conversation state, tools, API key or provider fallback. Meeting/version/profile guards run before sending (including after token renewal) and during streaming; deleting/editing/switching profiles invalidates stale reviews/results.

Summary prompts request bounded JSON as text. Validate schema, selected source IDs and exact supporting quotations; reject unknown references/malformed output. Derive timestamps from referenced segments. Owners/deadlines must be explicitly present in referenced transcript text, otherwise null/Unassigned/Not specified. Decisions have uncertainty, actions have Open/In progress/Completed/Cancelled status. Evidence validation is not proof of semantic truth: user review is required. Generated output remains an unsaved draft until explicitly applied. Versioned saves/section selection preserve manual edits; regeneration never automatically overwrites user content. Keep authored/generated provenance. Temporary summaries cover only retained context and saving them needs persistence permission.

Post-meeting notes are default off and have separate explicit current-meeting/source/account/model/expiry/one-attempt remote permission. Only deliberate End meeting qualifies; emergency Stop, Pause, device loss, lock, crash and quit cancel/revoke without remote work. End can stop capture and produce one bounded draft; it does not automatically save that draft. No empty-text requests, retries, renewed grants, startup replay or paid fallback. Busy/offline/auth/usage failures require later manual action. Root status/cancel and history status disclose generation. Manual/Live P7 remain independent; one existing AssistantController request slot prevents overlap.

## Dashboard, search and external output

Meetings uses actual saved data, truthful empty/error/locked states, pagination/date/status/tag filters/sort and lazy transcript retrieval. Search decrypts bounded batches in the unlocked worker, returns safe text snippets with progress/cursors, and persists no terms/plaintext index; caps/partial coverage are visible. Detail offers Overview/Transcript/Notes/AI, source-linked evidence, user edits/revert, action/decision controls, selected-meeting questions and follow-up drafts. Opening/resuming metadata does not acquire media; new capture always uses existing consent UI.

TXT transcript, Markdown notes, JSON and readable summary exports use native save dialogs and bounded output. Explicit clipboard copies are plain text. Email drafting invents no recipients and sends nothing; an independently approved mailto handoff opens the OS client with a size-bounded user-edited draft and no automatic send. Hosted share links and direct Gmail integration stay deferred; no fake link/service is presented.
