# P9: modes, personal knowledge, languages and templates

Baseline `bf92396`, 2026-10-28. P10 calendar/people, P11 enterprise and P12 mobile are excluded. Existing capture, speech, context review, provider and meeting systems remain the authority for permissions and lifecycle. No agent tools, paid fallback, cloud document store, OCR, embeddings service or model download is added.

## Checkpoints

1. **P9.1:** typed provider-independent modes, editor, duplication/reset/deletion protection and encrypted persistence. Initial gate: 84 targeted tests across mode/context/provider-controller suites and production build.
2. **P9.2:** native-dialog import, isolated extraction, authenticated storage and bounded local retrieval. Gate: 34 mode/knowledge tests; the combined language/speech/settings gate passed 69 cases. A later common-topic ranking regression adds coverage.
3. **P9.3:** global and mode response languages; current English-only tiny.en/base.en compatibility explicitly shown. Existing downloads/checksums/performance/cancellation remain unchanged. No multilingual model or capability claim is introduced. Combined gate above includes existing speech/settings regressions.
4. **P9.4:** four templates, custom editor, persistence/migration and P8 grounding/version preservation. Gate: 57 targeted template/mode/meeting cases, strict TypeScript. Later integration tests cover summary archives and clearing their derivatives.
5. **P9.5:** shared selection, source review/citations, separate Live knowledge grant, account/session cancellation, compiled workers/native credentials/Electron smoke and performance. Final evidence and exact counts are in [TESTING.md](../TESTING.md) and [DELIVERY.md](../DELIVERY.md). Genuine provider outcomes are reported separately from fixtures.

## Modes and precedence

`shared/modes.ts` defines identity, name, description, icon/category, instructions, response length/format/language, subtractive context preferences, action allowlist, document references, template reference, timestamps and built-in identity. General, Coding, Interview, Sales and Meeting implement the requested roles. Conversation remains as the legacy Conversation Assist mode. Explicit old `general`, `code`, `conversation` review presets map to General, Coding, Conversation; existing appearance/speech/account settings are untouched.

Main supplies the active mode to the existing `AssistantController`, P6 `contextPrompt` and all provider requests, including follow-ups, contextual actions, Auto-Hint acceptance, Live and meeting summaries. One shared selector appears in every shell. Capture sessions do not change the selected mode. Mode changes cancel reviews/requests and revoke automatic grants without acquiring media or sending inference. Built-ins may be edited/reset/duplicated, never permanently deleted. Custom instructions are bounded to 4,000 characters; 50 modes/profile. Settings hold a separate default mode used after explicit unlock; current selection remains session-local while locked.

Immutable provider instructions take priority over mode preferences. Templates only describe output sections. Captured/reference/document text is JSON-serialized untrusted data beneath those rules. No instruction can enable capture, add remote-sharing categories, obtain credentials, change billing, select an unapproved model or create tools. The provider transport remains `store:false`, `stream:true`, `tools:[]`, `tool_choice:none`, official plan OAuth/model discovery, terminal completion checks and cancellation; Claude remains default-off API-only with its existing explicit billing gate and no subscription login.

## Storage and profiles

`PersonalStore` hosts a separate SQLite worker and reuses P8 `MeetingCipher`, `MeetingKeys` and `historyProfile`. Its independent Windows Credential Manager service is `EveryHint.Personal.v1`; the key is never a renderer field or plaintext file. Profile identity hashes canonical installation home plus selected signed-in registration, with a separate signed-out local profile. Missing keys with existing databases fail closed. Wrong keys/profiles, corrupt or newer schemas preserve the database. Config has an authenticated encrypted record; schema migration 1→2 adds document/section tables transactionally. Config schema 1→2 supplies templates without replacing modes/language. Sensitive metadata (including names) and all extracted text are authenticated AES-256-GCM blobs, bound to profile/record/section with P8 AAD. Only opaque row IDs/counts, schema and file size remain visible.

Startup is locked: built-ins are available without opening the personal database. Explicit unlock loads small config/metadata, never full-document text. Lock/account changes/reload/crash/suspend/quit terminate workers, cancel import/retrieval/reviews, clear renderer scope and revoke sharing. Commands validate exact envelope keys, the existing trusted Electron sender/document and a main-issued scope before/after asynchronous work. Read results also check revision to refuse stale inspection/search data. Queues are bounded (one controller mutation/import, at most eight worker RPCs); RPC timeout is 15 seconds, with no write retry.

Only extracted text and metadata are copied into encrypted storage. Original PDF/DOCX/TXT/MD bytes are read from the explicitly selected source and discarded; the original path is not stored. Removing an app document transactionally cascades its encrypted sections, removes mode associations and invalidates reviews, displayed answers and ephemeral search/inspection. There is no persistent plaintext index or excerpt cache. It does **not** delete the user's source file or remote/exported copies. Keys are retained for the profile, consistent with P8 recovery; deleting a document does not delete other profile data. Same-OS-user malware, paging/crash dumps, backups and physical SSD erasure remain outside the protection boundary.

## Safe local extraction

The renderer supplies no path or file bytes. A native main-process dialog chooses one PDF, DOCX, UTF-8 TXT or Markdown document. A disposable parser worker reads the selected regular file with a bounded buffer and rejects a file that changes size while reading. Limits: 8 MiB input, 400,000 extracted characters, 200 PDF pages, 500 sections/document and 100 documents/profile. Worker V8 limits are 128 MiB old generation, 16 MiB young generation and 4 MiB stack; a 12-second wall timeout/cancel terminates it. These V8 limits do not cap all native/external allocations; adversarial resource exhaustion beyond the file/page/text bounds remains a release hardening/manual stress item. The Electron main/capture/Whisper loops never perform PDF/XML/ZIP parsing or SQLite search.

- **PDF:** pinned Mozilla PDF.js 6.4.299, bytes-only, text extraction, no rendering/action/JavaScript APIs, system fonts, worker fetch, streaming/range requests or WASM. Fetch is denied in the parser worker. Actual page numbers originate in page iteration. Partial page failures are disclosed; unusable/password-protected/malformed/no-text files are rejected. No OCR, invented pages or automatic cloud conversion.
- **DOCX:** fflate 0.8.3 extracts only `[Content_Types].xml` and `word/document.xml`, validating archive names/counts/duplicates/macros and expanded XML budgets before inflation (2,000 entries; 4 MB/body and 4.5 MB total selected XML). Saxes 6.0.0 validates content types, namespaces/body structure, XML well-formedness and depth. DTDs/entities/macros are rejected; relationships, scripts, embedded objects and external resources are never executed/fetched. Main body only: headers/comments and layout page numbers are not claimed.
- **TXT/MD:** fatal UTF-8 decoding, binary/control/text-size rejection. Markdown headings become section labels; markup remains text, with no HTML/script execution. DOCX/TXT/MD page is null. Very short/no-text input fails visibly.

Libraries: [Mozilla PDF.js](https://github.com/mozilla/pdf.js), [fflate ZIP filtering](https://github.com/101arrowz/fflate#unzip), [Saxes entity/DTD behaviour](https://github.com/lddubeau/saxes#regarding-doctype-and-entity). No external conversion service, vector database or model dependency was added.

## Retrieval and source limitations

Chunks are 1,200 characters with a 100-character overlap, preserving Markdown heading/PDF page where available. Unicode word tokens and local BM25-style inverse-frequency/length scoring rank relevant sections, with a small title/heading boost. English stopwords are removed from queries and meaningful keyword coverage is required. A fixed absolute score threshold was rejected after the large-library benchmark showed it suppressing common-topic matches. No semantic/vector retrieval, stemming or paid embeddings are implied; paraphrases and languages without word boundaries have limited recall.

Retrieval decrypts only enabled, selected, active-mode documents in the storage worker, at most ten documents/400,000 source characters each. It returns at most four deduplicated excerpts/4,800 text characters; serialized references consume additional prompt budget. Whole-request limits are rechecked after mode/template/knowledge enrichment; overflow is refused visibly. Library search examines ten enabled documents/page with explicit continuation; it is not an all-library global ranking. No whole-library startup load/upload occurs. There is no persistent decrypted search index; re-ranking is bounded work on demand.

Manual users choose documents, inspect the exact frozen excerpts/names/headings/pages/ref IDs and complete the existing one-use acknowledgement/Ask. Editing/importing never transmits. Answers retain the exact excerpts sent and mark a reference as cited only when its literal `[K:document:section]` appears. Unknown knowledge references are labelled unsupported. A literal citation or matching quote is **not semantic fact verification**; claims must be compared with the supplied text. The app does not label all generated statements as source-supported. It never invents page metadata.

Live knowledge defaults off. Authorisation independently requires retrieval enabled, remote sharing allowed and exact selected active-mode source IDs in the current permission preview; the grant also binds AI mode/account/model/capture/assistant scope. The existing P7 scheduler supplies those IDs internally, never a renderer permission override. Changed mode/source/account/settings, Pause/Stop, cancel or expiry revoke. Existing cooldown/cap/one-slot rules still apply. Uploading does not create an AI request. Excerpts sent automatically remain inspectable on the answer. Auto-Hint remains local and its acceptance prepares the existing review; it gains no implicit knowledge-sharing permission.

## Languages and templates

Global output language and per-mode override are bounded user preferences. `default` follows the question/system default; English and other named language preferences can be entered. The provider model catalog exposes no reliable language inventory, so suggestions are labelled best effort rather than advertised as verified provider capabilities. Follow-ups use the current mode; stored transcripts are not translated or transmitted for unrelated purposes.

The current pinned official whisper.cpp tiny.en (77,704,715 bytes) and base.en (147,964,211 bytes) are **English-only**. Existing explicit install, SHA-256 checks, local model memory diagnostics and P3 cancellation remain. Tiny.en is real-inference verified; base.en physical/quality acceptance remains pending. No multilingual model, new checksum, download, language detection or unsupported-language promise was added.

`NoteTemplate` stores bounded identity/name/timestamps and 1–7 ordered sections, each with heading, up to 400 characters of guidance and one unique existing P8 summary field. Built-ins: Standard Meeting (Overview/Discussion points/Decisions/Action items/Follow-ups), Interview Notes (Questions/Answers/Key observations/Follow-up topics/Summary), Sales Call (Customer requirements/Questions/Objections/Commitments/Next steps), Technical Meeting (Technical topics/Architecture decisions/Bugs or issues/Assigned tasks/Follow-up work). Custom sections map onto the existing grounded fields, preserving P8 evidence/action validation rather than introducing a parallel generator. This limits a template to seven distinct section categories. Editors support heading/guidance/order/add/remove/duplicate/rename/default/mode association/format preview; custom templates can be deleted and built-ins are protected.

Meeting generation freezes the selected template (explicit selection, otherwise mode template, otherwise default) in the P8 review. The provider still returns the existing strict evidence JSON, not executable application instructions. Saved drafts retain the template snapshot for display/export even if the library template changes/deletes. Summaries remain unsaved until Apply. Existing manual notes and edited-section acknowledgement are preserved; prior saved summaries/decisions/actions are archived only on Apply (normally three versions/250k characters, always retaining the latest prior version; record-size refusal preserves the committed version). They can be inspected in Overview and exported as JSON. Clear generated/transcript/delete/retention also removes archived derivatives. No automatic overwrite, invented owner/deadline or automatic email/calendar action exists.
