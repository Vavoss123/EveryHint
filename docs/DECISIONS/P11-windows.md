# P11 Windows desktop preparation — design and initial audit

Baseline `d9d1ca8`, Windows 11 Home 10.0.26200 x64, Electron 45, Node 24. P11 is Windows optimisation/privacy/personal desktop release preparation. Enterprise is permanently removed; mobile is not started. Preserve P1–P10 evidence, remaining physical/manual gaps, restricted historical temporary directories and consumed genuine-provider grants. No new genuine inference, public release, invented signing identity or update URL is authorised.

## Existing behaviour, inspected before implementation

`src/main/index.ts` creates one frameless main window, always-on-top preference, 80–100% opacity, sandbox/context isolation/no Node integration, restricted navigation/IPC/custom protocol and a separate invisible sandboxed audio host. There is **no setContentProtection call**. `ElectronScreenCapture` filters EveryHint windows from selectable sources and limits snapshots to 1600×900 JPEG; entire-screen selection can still include the overlay. Excluding own sources, minimising, hiding or changing opacity does not establish receiver-side privacy. No existing installer/updater/signing configuration exists. Version is 0.4.0 and the package description contains a pre-existing encoding error to correct during release preparation.

Capture serialises/deduplicates in-flight snapshots; speech queues and retained text are bounded. Native image sampling still decodes JPEG in main; renderer imports all dashboard modules eagerly. Measure actual short controlled profiles before deciding changes. Session Stop normally changes the capture session and clears inference, but same-session STOPPED/ERROR transitions only discard a review; add explicit cancellation regression. Quit currently launches workspace cleanup without awaiting it, and closes only some services inside its bounded shutdown barrier; make cleanup/Windows lifecycle deterministic without restoring capture or AI grants.

## Checkpoints and proposed boundaries

1. **Privacy:** retain legacy protection-off on migration; add acknowledged opt-in Windows content-protection preference, apply before showing the window, expose requested/configured/error/unsupported status and a permanent concise limitation. Electron readback reports configuration only. Native display-affinity inspection and owned-window local checks do not prove Discord/Teams/Zoom/recording capture support. Receiving-device, whole-screen/window/multi-monitor outcomes must be recorded as visible/omitted/black/partial only after real tests. No changes to sharing apps, drivers, capture pipelines or monitoring.
2. **Performance/reliability:** create local-only CPU/RSS/heap/event-loop/queue/worker profiles with synthetic capture and real cached Whisper; label hardware separately. Start three concurrent 30-minute controlled transcription/screen/combined runs once the harness is validated; disable real provider network and use mock Live. Profile initial/idle/streaming/Auto-Hint/retrieval and repeated lifecycle/restart. Optimise measured redundant publishing/decoding/eager rendering, not assumptions. Preserve review/drafts and bounded buffers. Stop/OS lock/suspend/crash must revoke inference/capture; shutdown awaits resource teardown with bounded fallback.
3. **Security/UI:** audit official Electron checklist and dependency advisories; keep deny-by-default permissions/CSP/exact sender and URL rules, secure OS tokens/encryption/source guards/model/helper integrity. Correct specific findings and improve privacy/status/version/keyboard presentation using existing EverySession tokens. No UI library or redesign.
4. **Installer/updates:** use maintained electron-builder NSIS, per-user assisted installer, stable application ID, branded icon/start menu/optional desktop shortcut, preserve user data on upgrade/uninstall by default. Package only explicit production outputs/resources/native dependencies and a checksummed trusted runtime; models remain explicit checksum-verified local setup. Produce a clearly labelled **unsigned private test artifact** only, never publish. Clean Windows installation, signing/SmartScreen/public eligibility remain external gates. NSIS uses electron-updater rather than Electron's Squirrel-only update path; without an authenticated release host/signing infrastructure, expose disabled safe update foundation/status with no remote download/install code or invented endpoint.
5. **Endurance/acceptance:** record actual elapsed runs, environment, CPU/RSS/worker/queue/responsiveness/cleanup/crashes. Fixtures are not physical hardware acceptance. Maintain an evidence matrix separating automated, genuine provider, real hardware, human UI, pending, blocked and failed, plus release blockers and installer commands/artifact paths. Update all seven docs and feature inventory, permanently removing enterprise from planned scope. Commit verified changes as `feat: prepare EveryHint Windows desktop release`; no distribution or mobile work.

## Official sources reviewed

- [Electron BrowserWindow content protection](https://www.electronjs.org/docs/latest/api/browser-window#winsetcontentprotectionenable-macos-windows): Windows display affinity; composition delay and capture-method caveats. `isContentProtected()` is configuration readback, not receiver verification.
- [Microsoft SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity), [GetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowdisplayaffinity): protects only supported public capture APIs, not a general security/DRM guarantee. Do not promise invisibility or undetectability.
- [Electron security](https://www.electronjs.org/docs/latest/tutorial/security), [performance](https://www.electronjs.org/docs/latest/tutorial/performance), [updates](https://www.electronjs.org/docs/latest/tutorial/updates), [NSIS configuration](https://www.electron.build/nsis/). Verify installed packager configuration/schema and upstream docs before building. No production signing/update identity exists.

Initial dependency audit: `npm audit --json` reports **zero known advisories** on the baseline. This is not proof of absence of vulnerabilities. Available electron-builder registry version is 26.18.0; pin and re-audit after installation. Checkpoint results are appended only after execution.

### Final update scope

The user explicitly requested a new-version update feature and then chose **keep updates unconfigured until signing and hosting are ready**. Final implementation includes manual Check/Download/progress/Cancel/confirmed Restart, using electron-updater 6.8.11 with background download/quit installation/web/differential/prerelease/downgrade disabled. Bundled policy remains disabled/empty. EveryHint authenticates canonical metadata with a pinned Ed25519 key and independently rehashes/checks valid full Windows publisher before install. This is explicit application verification, not a claim that stable 6.8.11 supports upstream next/v27 signed manifests. Ten update unit cases plus actual Windows positive/wrong-publisher/unsigned rejection pass; no genuine release feed or signed app update was available. A positive Windows check caught module progress on stderr; progress is suppressed while errors still reject. Operator-only metadata tooling creates no keys and publishes nothing. [Final architecture and activation gates](../UPDATES.md) supersede the original foundation-only proposal; public release remains blocked.
