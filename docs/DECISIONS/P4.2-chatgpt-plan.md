# P4.2 — ChatGPT plan inference, 2026-10-27

Live verification on **2026-10-28 succeeded** with **gpt-6.1-sol** using EveryHint's own SIWC ChatGPT plan grant and the public Responses endpoint. The approved question was **Reply exactly: EveryHint is connected.** The actual completed answer was **EveryHint is connected.** No screenshot, transcript, history or raw audio was sent. The response reported **167 input / 9 output tokens**, first text in **4.214 s** and completion in **4.299 s**. No API-key/provider fallback or paid Claude request was made. These are a single observation, not a latency guarantee, quota balance or dollar-cost estimate.

Two plan requests were made, each separately authorised. The first was rejected by an overly strict SSE MIME check before any text was displayed. The corrected parser validates bounded SSE data frames independently of MIME metadata, still requires response.completed, rejects non-streaming JSON as completion and cleans up its reader. Three regression cases cover this. The second authorised request completed genuinely; no automatic inference retry occurred. Either attempt may consume the user's plan allowance.

## Diagnosis and decision

P4.1 launched the official Codex CLI login with an isolated home and required OS keyring. That establishes a Codex-client session; it does not establish an EveryHint OAuth registration, host binding or user grant for direct ChatGPT plan inference. The SDK adapter also deliberately refused inference: SDK 0.164.0 has no supported, fail-closed deny-all built-in-tool boundary. Read-only filesystem access still permits commands. Removing that restriction would violate the answer-only requirement.

P4.2 uses the official **Sign in with ChatGPT open-source/local registration flow and public Responses API**. The current request explicitly permits and prefers this pathway when it avoids agent execution permissions. It supersedes the earlier runtime-only clarification. The model receives no tools, and no Codex agent, shell dispatcher, file editor or computer-control process starts. The Claude provider remains a separate, disabled-by-default API adapter; subscription sign-in is still unavailable without Anthropic approval. No paid Claude verification was authorised.

The old Codex actor/adapter and their tests remain as historical, restricted code, but application startup no longer uses them. Existing Codex/IDE credentials are neither read nor migrated. The internal provider ID `codex` remains an IPC compatibility identifier; the UI calls the active transport **ChatGPT · plan usage** and does not describe direct Responses answers as Codex runtime execution.

## Registration and credentials

The browser flow uses the documented dynamic client only for a new registration. EveryHint retains the issued client and stable per-installation host identity. Returning sign-ins reuse that registration. PKCE S256, fresh state and nonce, exact IPv4 loopback callback binding, single-use code consumption, verified RS256 ID/access JWTs, issuer/audience/subject/client matching and plan-scope checks precede activation. Identity-only consent cannot request models or inference. **Grant ChatGPT plan permission** explicitly requests consent again; the deployment-dependent `force_reconsent` flag is not sent. See [official sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) and [token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference).

All tokens and account bindings live in the native OS credential store through pinned `@napi-rs/keyring` 2.1.2; `jose` 6.2.13 validates JWT signatures/claims. Windows credential-size limits require 2,000-byte binary chunks. A single manifest commits a complete, hashed generation; refresh writes are serialized and old chunks are removed after commit. Failures never select plaintext storage. Crashes or native deletion failures can leave OS-protected orphan chunks; this is not a claim of secure erasure. Only the nonsecret `host-id` file is stored under `userData/chatgpt-plan`. At most four saved registrations are supported, with a 128 KiB vault limit.

A saved registration is distinct from its email label. The renderer receives only account labels, opaque local IDs and safe status. Sign-out attempts refresh-token revocation through validated official discovery, clears that registration’s tokens locally, and retains its client/subject binding for reconnection. Failed remote revocation is reported explicitly. Refresh happens only during an explicit model-list or Ask action near access expiry, respects the refresh window, omits scope, and commits rotating credentials together. Terminal refresh failures clear the unusable session; transient errors retain it. See [profiles and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions).

## Inference and context

**Refresh ChatGPT models** makes an explicitly authorised GET to `https://api.openai.com/v1/models`, keeps visible `models` entries in server order, and requires a user model choice. A five-minute account-bound in-memory catalog is advisory. A listed model is not labelled verified until its response completes. Unknown image metadata disables screenshots; only explicit `input_modalities: ["image", …]` enables them. Account changes invalidate the catalog and conversation.

Only Review → fresh transfer acknowledgement → Ask can POST to `https://api.openai.com/v1/responses`. The frozen review includes the chosen model, question, independently selected current-session final microphone/system text, optional supported screenshot and selected bounded history. The transport sends `store: false`, `stream: true`, `tools: []`, `tool_choice: "none"` and the fixed untrusted-context instruction. It uses no unsupported output-token/temperature parameters, previous-response IDs, hosted conversation or background job. Only `response.completed` establishes success. See [official model discovery and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference).

The stream parser bounds event/total bytes, handles split UTF-8, preserves partial text on failures, rejects tool output, and stops its reader on cancellation. Incomplete/error/interrupted streams are failures. HTTP 401/403/404/429/5xx, missing plan grants and terminal usage failures have safe messages, validated provider codes and request IDs. Raw HTTP bodies, OAuth descriptions, tokens and browser URLs are not logged or passed through IPC. There are no automatic inference retries, alternate endpoints, API-key fallback or provider fallback. See [official errors and recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery). The [app-server alternative](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server) is unnecessary for this answer-only integration.

Treat EveryHint as a private-use prototype intended for eventual distribution. The user separately authorised the initial synthetic text-only attempt and one corrected-build retest. **Real browser sign-in, a signed plan-usage grant, model discovery and one genuine completed gpt-6.1-sol answer are verified. Other models/accounts, real captured-context transfer and release acceptance remain open.** Local fixtures and an existing unrelated Codex login do not establish entitlement. No quota, unlimited use, commercial approval or production readiness is claimed.

Before distribution, establish eligibility for this open-source/local route and the applicable approval/registration route for any paid or hosted offering.
