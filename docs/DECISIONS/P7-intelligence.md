# P7 design: local intelligence and bounded Live Assist

Baseline: e68bfe7. Design recorded before implementation, 2026-10-28. P7.1 detection/correlation is verified before P7.2 actions/UI, then P7.3 authorisation/scheduling. P8 meeting history is outside scope. P5 Windows/hardware/endurance checks stay open. The four P6 editor profiles in Windows Temp must not be removed without the user's approval and an unused-state check.

## Reuse and boundaries

CaptureSessionController remains the capture authority; final TranscriptEvents come from the existing Whisper store. AssistantController, ai/context.ts and ChatGptProvider remain the sole request/review/transport pipeline. Immutable instructions, model capability checks, bounded JPEG/text/history, explicit account-specific catalog, store:false/stream:true, empty tools/tool_choice:none and terminal response.completed are unchanged. No server conversation state, raw-audio sharing, API fallback, new classifier/runtime download or file/tool executor is introduced.

Main owns a bounded event-driven local engine with stable event/capture-session IDs. It consumes only selected consented final transcript events and selected native frame observations while capture is ACTIVE. Manual skips automatic analysis. Auto-Hint prepares at most three ranked local suggestions, never inference. Local events include QuestionDetected, KeywordDetected, ScreenChanged, ContextUpdated, SuggestionCreated/Dismissed/Expired and AssistRequested/Completed. Context expires and resets at session/account boundaries; no behavioural profile or meeting archive is persisted.

## P7.1 detection/correlation

English question rules combine punctuation-independent interrogative/help patterns, incomplete/rhetorical/reported-speech suppression, task relevance, nearby final context and an explicit heuristic confidence threshold (not a calibrated probability). Final IDs and normalized token similarity suppress provisional/final, repeated and cross-source echo triggers. A small dependency-free classifier comparison uses separate deterministic development/evaluation fixtures; production changes require measurable held-out benefit and disclosure that synthetic English fixtures do not prove real call accuracy.

Screen analysis hashes encoded frames before lazily reducing changed frames to a 32×18 intensity grid. Mean/fractional pixel differences plus a stable second observation debounce meaningful changes. Only hashes/grid/metadata are retained by intelligence; the existing capture service retains its ordinary current frame. A screen change is never classified as a question or an error without evidence. It produces a local review candidate only; automatic inference requires an additional eligible final spoken question. Timestamp/source correlation can attach the authorised current screen to that question, without claiming semantic recognition.

Windows.Media.Ocr was evaluated as a supported interface: Microsoft documents package identity requirements for desktop callers and device language availability. The current unpackaged Electron prototype has no native WinRT bridge. P7 starts with measured perceptual changes and the existing direct-image model path; OCR/accessibility text recognition is not added or claimed without its own accuracy/performance/platform evaluation. Source exclusion applies to the selected capture source, not selective masking of arbitrary apps inside a whole-screen image.

## P7.2 contextual actions

Typed action handlers expose eligibility, fixed instructions, bounded input and review/local-result outcomes. Get Answer, What Should I Say Next, Follow-up Questions, Recap and Dynamic Suggestion use the shared context builder and one-use transfer review. Fact Check requires a specific claim and is permanently labelled unverified/context-only because no external retrieval is configured. Recap explicitly states the selected retained window. Who Am I Talking To uses only explicitly provided participant information; absent data returns unknown locally, never biometric or calendar inference. Presets remain lightweight; no P9 editor.

Suggestions rank relevance/confidence/freshness/correlation and penalise repetition, dismissals and recent answered questions. Accept prepares a review; Dismiss and Dismiss Similar apply to this in-memory capture session. The top suggestion is keyboard reachable. The existing compact/expanded/dashboard and EverySession tokens are reused, with visible mode/sharing state and root Pause/Stop controls.

## P7.3 separate expiring permission and central scheduler

Live Assist is off at startup and requires an explicit acknowledged grant. It binds current ChatGPT account, selected model, assistant conversation, capture session/epoch, exact screen/window ID, allowed microphone/system/screen/history categories, high-confidence final-question event type, expiration, minimum interval and request limit. Defaults: 30 minutes, at least 30 seconds between attempts, at most 20 attempts. Settings persist limits/local analysis choices, never mode or authorisation. No monetary conversion of subscription usage is claimed. Claude cannot receive automatic requests.

Only one scheduler may reserve an automatic attempt. It checks the live grant, current identity/model/readiness, selected question's shared source, capture state/epoch, source exclusions, age/confidence/relevance, duplicate history, cooldown/request limit, manual review/request conflicts and expiration before preparation and again immediately before the existing ask. It may acquire one fresh authorised screenshot through P6. Unchanged images are not re-uploaded; automatic work may omit an unchanged already-sent image and disclose that omission. No fallback to an unselected source/provider is permitted. Reservation counts failed/uncertain attempts conservatively; there is no usage-error retry or unbounded queue.

Pause, Stop, expiry, cancellation, source/model/account/provider/settings changes, Clear, lock, suspend, reload, renderer failure and quit revoke the grant and cancel pending preparation/automatic inference. Resume never restores it. Low-confidence questions remain optional suggestions. Screen changes alone never submit. Suggestions generated before authorisation cannot become retrospective automatic requests. Existing Manual/Auto-Hint review/acknowledgement stays mandatory.

## Verification and live work

Checkpoint tests use injected clocks, native samples, final transcript fixtures and synthetic provider transports, including races during screenshot capture and token inspection. Measurements cover detection time, sample cost, bounded memory/events, proposal frequency, duplicate suppression, request frequency, response latency and queue depth. Genuine automatic inference requires a fresh explicit user authorisation for one deliberately initiated, scoped test. A synthetic event proves scheduling/transport only; physical microphone/playback/DPI/endurance acceptance remains separate.

Sources consulted: [OpenAI plan preview limits](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), [Microsoft Windows.Media.Ocr](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr?view=winrt-26100). Actual checkpoint results and remaining acceptance will be recorded in TESTING.md/DELIVERY.md.

## P7.1 checkpoint verified

400 unit tests (367 baseline plus 33 local/benchmark cases), strict TypeScript and zero-warning lint pass before P7.2 work. The synthetic 22-development/32-distinct-evaluation comparison measured rules at 16 TP / 0 FP / 0 FN / 16 TN versus a unigram Naive Bayes candidate at 6 TP / 1 FP / 10 FN / 15 TN (0.85 threshold). This small authored fixture does not establish real conversation accuracy. The candidate did not improve both precision and recall; production keeps inspectable conservative rules without a dependency/model download.

One observation: 3,200 rule calls took 14.18 ms (mean 0.0044 ms, p95 0.0078 ms); 1,000 unchanged JPEG hash observations took 6.67 ms with one sampled grid. Native image decoding is not included in that hash-only measurement. The isolated test process reported 16 ms user CPU and about 68.8 MB RSS; heap delta was negative after GC, so it is not an app memory saving claim. Bounded-session/duplicate/stale/source/order/perceptual/stability tests passed. Evidence: ignored artifacts/p7-local-benchmark.json. No remote inference or hardware capture occurred in P7.1.

## P7.2 checkpoint verified

426 unit tests, strict TypeScript/lint/build, 44 existing AI + 44 existing UI Electron checks and 20 new intelligence Electron checks pass before P7.3. New action tests cover all seven handlers, local unknown/user-provided participant results, permanently unverified claim assessment, retained-window eligibility, correlated excerpt IDs, at-most-three ranking, dismiss/similar/expiry, account/provider clearing, excluded-utterance protection and strict IPC/preferences. UI checks cover Manual startup, Auto-Hint without transmission, safe participant text, shared frozen action review, invalid limits, compact geometry, keyboard focus and restart without mode/grant/capture. Renderer suggestions are labelled fixtures; forged acceptance fails in main. An existing compact assertion now waits for actual visibility after its asynchronous layout change; original coverage remains intact. No real P7 provider request or hardware capture occurred at this checkpoint.

## P7.3 checkpoint verified

458 unit tests / 35 files, five actual local HTTP/native-vault fixtures, six installed Claude SDK loopback tests and 174 Electron assertions pass. The new Live suites cover exact separate consent, source/account/model/session binding, future-question-only scheduling, one active request and one fresh pending candidate, cooldown/cap, removed excerpts, screenshot/token races, monotonic expiry/cooldown, clock jumps, auth/rate/network errors and cancellation without retry/fallback. The official provider receives the unchanged body; the internal permission predicate runs after token retrieval before POST and for streamed events. Root/tray/title sharing indicators and compact 125% geometry are verified separately from human DPI acceptance.

The first scoped synthetic-audio test exposed delayed permission-preview publication: readiness reached the public getter before it was pushed to the renderer, so the question finished before consent and was correctly suppressed as pre-existing. Source/Whisper/model readiness now publishes independently of new speech, with a dedicated regression test and no repeated identical publication. A gated fixture starts actual audio only after the UI grant; real Whisper plus a clearly labelled local provider completed once and closed at cap. Genuine automatic OpenAI completion remains pending separately requested replacement authorisation. No physical microphone, system playback, screen or historical chat was used.

Native screen sampling on a generated 1600×900 JPEG: 50 operations, mean 4.385 ms / p95 5.849 ms, 576-byte retained grid, about 267 MB isolated main RSS. This is not whole-app endurance evidence. English-only rules, fixed keyword cues, perceptual-only screen changes, no independent fact retrieval/identity research and the five-minute catalog limitation are explicit. P1–P6 physical/visual and P7 real-call/15-minute gates remain open. P8 has not started; restricted P6 editor profiles remain untouched.
