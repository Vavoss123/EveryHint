## Daily workflow

Open EveryHint → Start EveryHint → approve the selected local sources and optional ChatGPT sharing types → continue the conversation → **Ctrl+Alt+Enter**. The separate floating assistant opens/focuses immediately and streams one answer. Alternatively, type **help** or a question and press **Enter**. **Shift+Enter** inserts a newline. The normal floating view shows the latest answer, mode, Listening/Paused/Idle state, input/Ask, Hide and Pause/Stop. Answer text scrolls within the panel; the composer and session controls remain visible. Model/timing/token diagnostics are in Advanced Settings.

Missing speech setup appears in Start with an explicit local-model download action. Start checks the existing helper and model integrity before capturing audio, then automatically enables the existing native Whisper worker. No advanced-panel Enable action is required. A speech startup failure stops the new session; a later worker failure stops managed capture with an explanation. Source preferences are remembered, and capture acknowledgements and sharing grants are fresh for each session. Existing custom modes, encrypted meetings, knowledge, calendar, People/memory, Live Assist, protection, retention and tray/window controls retain their original engines.

| Action | Default binding | Behavior |
| --- | --- | --- |
| Answer from conversation | Ctrl+Alt+Enter | Focus overlay and trigger one scoped conversation request |
| Show/hide floating assistant | Ctrl+Alt+Space | Change visibility without changing capture |
| Pause/resume | Ctrl+Alt+P | Stop/restart authorised capture and local transcription |
| Stop | Ctrl+Alt+Shift+X | Stop capture/transcription, cancel pending inference and clear sharing |
| Compose/review context | Ctrl+Alt+A | Preserve the existing explicit context review workflow |
| Clear conversation | Ctrl+Alt+Shift+C | Cancel/reset AI memory and invalidate the conversation sharing grant |

All six use Electron `globalShortcut`; Settings displays actual configured bindings and registration results and supports rebinding. Duplicate bindings fail validation. Upgrading an older custom Enter binding preserves it and chooses an unused Answer binding. An existing personal instance owned the five older defaults on this host, so the isolated native tests rebound those five to Ctrl+Alt+Shift+Space/P/Z/A/V. **Answer was tested at its proposed default Ctrl+Alt+Enter and rebound to Ctrl+Alt+Shift+Enter.** The personal instance was left running. Occupied default registrations were observed and reported, not certified as working.

## Context and permissions

The new main-owned `ListenController` coordinates the existing P2 capture session, P3 transcription store/worker, P7 question detector, P6 context builder/AssistantController and official ChatGPT Responses transport. It does not implement another capture, recognition or provider pipeline.

1. **Local capture:** fresh source/participant acknowledgement starts only the chosen microphone, Windows system audio and/or selected screen/window. Raw audio remains transient and local. Existing explicit transcript persistence is independent and remains opt-in.
2. **Session sharing:** a separate acknowledgement selects transcript and/or screen. The in-memory grant binds capture session, account/plan permission, provider, selected model, AI mode and assistant session. It expires after at most one hour, checked with wall and monotonic clocks. It is never saved/restored. Stop/new session, account/provider/model/mode/context changes, expiry and explicit revoke invalidate it. Startup account/mode and asynchronous permission races cannot transfer a grant. Pause blocks/cancels requests and clears preview; the same grant may remain for deliberate requests after resume. Existing Live and End notes permissions remain separate; the Revoke sharing control/tray action also revokes them.
3. **Individual trigger:** Answer, Ask or Enter requests exactly one answer. Capture/transcription/screen sampling and scope approval do not make inference requests. Requests are reserved once, have the existing timeout/cancellation guards, and have no queued retries or provider fallback. A deliberate conversation request revokes competing automatic assistance; it cannot authorise Live.

The request uses eligible **final** transcript segments from the current session and approved captured sources, chronologically ordered, with source labels and timestamps. It excludes partials, old sessions, future/invalid timestamps and transcript IDs removed through the original review. The window is **120 seconds**, at most 100 candidate events, **6,000 transcript characters** and **20,000 serialized text characters** including mode instructions. The existing builder trims to its budgets. New local transcript retention defaults to two minutes, while stored retention choices remain. No extra unbounded transcript buffer is added.

P7 detects the latest complete clear question locally. With no typed question, it becomes the bounded request question; otherwise trusted application guidance asks for useful help grounded in supplied context without inventing a question. Typed say-next, code explanation, latest-question and summary requests use the same scope and state missing context honestly. No available final transcript or approved screenshot produces a local explanation and **zero inference**. Provider-fixture tests verify question selection and context delivery, not genuine answer quality.

Screen capture retains P2's one bounded latest frame. Each screen-approved request obtains a fresh native JPEG from the selected source through P6 (at most 1600×900, 1.5 MB, fresh within 10 seconds). Screenshot timestamps follow recent speech in the request. Another deliberate request can include an unchanged fresh screen; legacy reviewed-image and automatic Live deduplication remain. No continuous upload, OCR pipeline or raw-audio transmission was added. `View Context` retrieves one exact last bounded request on demand, with labelled text and image/time, rather than broadcasting images in Listen state. That preview clears on revoke/pause/stop/change and is discarded on access after two minutes.

Ordinary Listen requests include no prior answer history, knowledge documents, saved meetings, calendar, People or memories. **Attach Context** retains the existing exact review and fresh per-request acknowledgement for those extra types. Modes can further restrict the approved types/actions; their instructions cannot grant sharing, tools or billing. All captured/reference content remains untrusted. Renderer IPC accepts a bounded question or exact permission/start schema; it cannot submit its own transcript, screenshot, automatic flag or arbitrary expanded context.

ChatGPT readiness uses only app-owned registration/plan permission and validated catalog metadata. An explicit sharing/Ask action can refresh expired metadata, preserving an existing selected model if still available and failing if it disappears. Initial selection prefers verified image-input metadata from the returned catalog. Catalog visibility does not prove inference access; existing completed-response verification and errors remain honest. Startup makes no catalog/inference request. Responses retain `store:false`, `stream:true`, `tools:[]`, `tool_choice:none`, token/source/account checks and abort guards. No API-key or separately billed fallback was added.

The five plan integration cases, six SDK loopback cases and 12 actual native encrypted-storage assertions pass. All P1–P11 Electron suites are rerun: core 47, AI 44, speech **12** (including automatic Start), UI 47, intelligence 28, meetings 42, personal 34, context 36, Windows 20, UX 45, plus the new Listen suite **36**, for **391 Electron assertions** in total. The structured receipt contains the final Listen count and combined total. The P2-only regression deliberately retains the original low-level capture IPC with an empty speech installation; the separate speech and Listen suites verify the new automatic transcription path.

On actual Windows 11, the Listen suite uses an owned Windows Forms window in a separate PowerShell process. It verifies the foreground HWND/process before synthesising the OS key combination, actual native shortcut registration/rebinding, overlay visibility/focus, automatic native tiny.en recognition of synthetic microphone/system-audio speech, selected native window capture, the actual request body/stream, typed Enter/Shift+Enter, optional context, hide/pause/resume/Stop during streaming and cleared permission/context. OAuth signatures, model catalog and Responses are deterministic HTTP fixtures installed by Playwright in the isolated main process, never a production bypass. The owned temporary identity is signed out and the profile/test process is removed. Local screenshots and raw run logs are under ignored `artifacts/listen/`.

**Still unperformed:** physical microphone speech, physical Windows playback/loopback devices, human key presses, VS Code/Chrome/Discord-specific foreground acceptance, screen-sharing receiver/protection certification, genuine new ChatGPT/OAuth/Google inference and answer quality, clean-machine installer/upgrade/signing/distribution and retained mixed-DPI/accessibility/hardware gates. No receiving application or monitoring/proctoring control was bypassed. The separate native test application's focus proves the controlled cross-process scenario only. Genuine provider verification needs a fresh explicit budget. Version stays **0.5.0**; distribution remains **NO-GO** under the retained release gates.

Reproduce: `npm run check`, `npm run test:plan`, `npm run test:ai-sdk`, `npm run test:meetings`, `npm run smoke:listen`, and the ten retained smoke scripts listed in the structured receipt.
