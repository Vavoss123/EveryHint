# Windows RC manual procedures

These are **prepared procedures, not completed results**. Use [RC acceptance](RC_ACCEPTANCE.md) and the [observation CSV](evidence/rc-manual-observations.csv). The tested baseline is 0.5.0 / `ead3ec9`; do not label it 0.5.1. Stop if an approval/environment prerequisite is missing. Never weaken OS/app security, alter a sharing application's capture pipeline, or treat content protection as undetectability.

## Common test setup and evidence

Use disposable Windows 10 and Windows 11 test environments with an approved build and a second receiving device. Keep real personal/work material out of the test desktop. Record sender/receiver OS/build, app versions, installer SHA-256/signature state, CPU/RAM/GPU, microphone/output devices, monitor layout/resolutions/DPI, recording backend if exposed by the app, time and tester. Leave default sharing/capture settings intact unless a later explicitly recorded test varies a normal supported option. No internal/legacy capture flags, injected hooks, driver changes or bypasses.

Start EveryHint in a new empty **test-only** profile, with capture/transcription/Live off and no real account required for screen privacy. Use an unsent composer draft such as `RC VISUAL CANARY 07 — no private data`. Open another harmless window with different changing text. Set opacity to 100% and keep EveryHint visible over that window. Do not submit the draft. Confirm the actual sharing source is the intended monitor/window.

For every external case:

1. Protection **off**: show the canary and move the overlay. The receiver/player must confirm the positive control for scopes that include EveryHint. If it is already absent, the test cannot prove protection changed anything; record the control and reason as inconclusive.
2. Protection **on**: confirm EveryHint's UI says configured (otherwise record failure/unavailable and stop using sensitive content). Stop/restart sharing, then inspect the receiver after composition settles. Record visible/omitted/black/partial/not-selectable/inconclusive, not “invisible”.
3. Keep observation running while toggling off/on, moving/resizing the overlay, switching compact/expanded/dashboard, minimizing/restoring and stopping/restarting sharing. Record any initial/transient/partial disclosure and timing. Recheck both monitors where present. Do not assume a transition is safe because steady state looked omitted.
4. Restart EveryHint with protection enabled; confirm the preference/configuration returns while capture and Live remain off. Repeat the receiver check. A local preview is not sufficient.
5. Stop the test session. Record receiver observations and canary result per scope/OS. Preserve only harmless evidence; restore deliberate test preferences. Any personal content unexpectedly included ends the test and must not be transmitted as test evidence.

Windows exposes `WDA_EXCLUDEFROMCAPTURE` from Windows 10 version 2004; earlier behavior differs and there is no strict protection guarantee. EveryHint's configuration/readback is not proof about a particular sharing method. [Microsoft API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity), [Electron window API](https://www.electronjs.org/docs/latest/api/browser-window#winsetcontentprotectionenable-macos-windows).

## I — Clean install, genuine upgrade and uninstall

Perform independently on Windows 10 and Windows 11, using a standard test user and approved disposable VM/machine checkpoint. **Do not install over the operator's existing personal EveryHint installation.** A workspace/unpacked launch is not clean installation.

1. Record a clean checkpoint and artifact identity/signature. If Windows/security policy refuses the unsigned build, stop with BLOCKED and obtain an approved build/environment; do not click through, disable protection or create exceptions to manufacture a pass.
2. Install for the current user. Confirm branding, path, no elevation requirement, Start menu entry and desktop shortcut **unchecked** choice. Repeat from a clean checkpoint with shortcut checked. Check the installed version/protocol, launch, tray, hotkeys and that capture/Live/billing start off.
3. Verify explicit local model setup. Before model installation transcription must remain unavailable with accurate guidance; no implicit model download. Use only an approved cached model or deliberately choose a model download, then verify its checksum and offline operation. The helper must come from the installed resources, not a development cache.
4. In that synthetic test user/profile, create known fixture records: meeting title/manual note/saved final transcript, one harmless knowledge document, mode/template, local People/memory settings and retention choices. Use test accounts only if authentication testing is separately approved. Record IDs, semantic contents and local file hashes without exporting credential secrets.
5. For a **true upgrade**, install the previous 0.5.0 release, create fixtures there, close it normally, then install a **distinct newer** approved candidate under the same Windows user and stable application ID. Verify retained content, keys/credentials, preferences/models/retention, one installed app and working shortcuts/uninstaller. Replacing 0.5.0 with 0.5.0 is repair/reinstall, not upgrade. There is currently no justified 0.5.1 installer, so this gate remains pending.
6. Use Windows Installed apps/Apps & features to uninstall. Confirm app-owned binaries/Start menu/selected desktop link and running processes are removed. Confirm encrypted user data, models and credentials remain as documented. No recursive `%APPDATA%`, `%LOCALAPPDATA%`, credential-store or profile deletion is permitted. Test unrelated sentinel files outside the install directory remain untouched.
7. Reinstall the approved candidate and explicitly unlock fixtures. Confirm semantic preservation and no automatic capture/Live/AI. Check a separate standard Windows user sees no other user's data. Keep credentials tied to the original test OS user; copying SQLite alone does not back up OS-protected keys.
8. Retain/restore the disposable checkpoint according to the test environment's policy. Only explicitly owned fixture profiles may be removed; never clean broad Temp or historical P6/P8 directories.

## D — Physical audio, device performance and lifecycle

Requires operator approval for the named devices and capture scope. Earlier physical checks were explicitly kept pending; these procedures do not revoke that choice. Use no personal conversations, notifications, documents or real AI by default.

1. Microphone-only: explicitly authorise that input, speak a fixed harmless phrase, verify levels/final text/source provenance. Mute/unmute; select another named input; unplug/reconnect; deny/revoke permission. Confirm accurate failure, stopped tracks/worker and no invented transcript. Screen/system audio must stay off.
2. Loopback-only: play a harmless local fixture on the chosen Windows output, explicitly authorise system audio, verify text/levels and independent source attribution. Switch output devices, stop playback and revoke permission. The microphone must stay off. A synthetic WebAudio stream does not satisfy this test.
3. Repeat mic+loopback and screen+audio combinations with one approved display. Test Pause/Resume/Stop and fresh consent. Verify Stop clears capture and pending sharing, does not auto-resume or send AI, and leaves no helper/audio window. Record actual media failures and visible error/recovery.
4. Performance: use the same device/OS/build/power mode, model/thread count, capture rate, display layout and workload for baseline and candidate. Record cold/warm startup; idle; each source; Whisper; Auto-Hint; combined; long conversation/storage load. Collect process/worker CPU, working set, queue/drops, IPC/UI latency and cleanup every 10 seconds, plus an approved 30-minute combined run. State whether CPU is per-core or normalized and whether memory includes shared pages. Do not compare the RC's all-process CPU to P11's Electron-only metric. Real AI streaming/Live needs U01 first; a local mock remains a mock.
5. Set pass limits **before** matched comparisons: no crash/stuck session or unbounded queue, stable retained buffers, usable emergency controls and no unexplained sustained resource/latency regression. Investigate differences with repeatable traces instead of declaring a single faster sample an improvement. Retain before/after values and device conditions.
6. With fixture data saved, test Windows lock, sleep/resume, display disconnect and actual OS permission changes. Confirm stores lock and remote/capture grants are revoked; explicit user reactivation is required. Test active Quit and full restart, tray Hide versus Quit, shortcut conflicts and a second instance. Record physical shell behavior independently of DOM/hotkey registration tests.
7. In a **disposable** fixture profile/VM, simulate unexpected app termination, reopen and inspect interrupted saved records/ciphertext/key recovery. Do not power-cycle a personal machine or remove real keys. Missing keys must preserve encrypted data and fail closed without generating replacement keys/plaintext fallback.

## K — Accessibility and DPI

Use native Windows display scaling at 100/125/150/175/200%, including mixed monitors, independently of browser zoom. Move/resize/minimize/restore all three layouts and keep question/answer/Pause/Stop/Cancel reachable. Inspect streaming/code/transcript/Live, Meetings/Knowledge/Calendar/People, settings and empty/error/locked states. Record clipping, focus order and readability.

Using only keyboard, traverse skip navigation, main navigation, composer/review/removal/acknowledgement, source selection, save/unlock and settings. Check visible focus, Space/Enter behavior, no trap and focus return after dialogs. Run Narrator for role/name/state/progress/error announcements. Enable actual Windows high contrast and reduced motion in the dedicated environment; inspect selected/disabled controls and contrast. Browser media emulation/basic DOM labels are supporting automation only. Do not start an AI request as part of a keyboard test without a separate grant.

## O — Genuine packaged accounts and provider acceptance

An operator must choose approved test accounts. These actions can change account sessions/permissions and need deliberate consent; fixture registrations are not genuine sign-in evidence.

1. From a clean installed test profile, choose Continue with ChatGPT. Observe the system browser, app identity, consent text/scopes and return to the app. Do not copy passwords, tokens or browser cookies into reports. Validate cancel/deny/wrong-state/timeout behavior and confirm capture/Live remain off.
2. Authentication-only acceptance must stop before Ask. If permitted, explicitly discover the account's model list; that is a real provider call even though it is not inference. Test identity-only/no-plan behavior, expiry/reconnect, restart and isolated profiles. Treat provider errors and missing approvals as observed blockers.
3. Connect test A and B deliberately; save different synthetic records under each; switch while a reviewed draft exists and confirm review/remote grants are invalidated, stores lock, and no content crosses accounts. Sign out of one approved test session, verify local clearing and the provider's revocation outcome; other registrations and unrelated apps must remain intact. Local tokenless sign-out does not verify this behavior.
4. A genuine packaged answer or Live test requires a **fresh explicit** grant naming account/model, exact harmless payload/sources, maximum requests, whether a retry is allowed, and cleanup. Prior milestone grants cannot be reused. Do not grant screenshots/microphone/system audio/personal documents implicitly. Start with a reviewed synthetic text payload; separately scope any physical-source/Live request and its expiry/cap/cooldown/Pause/Stop/account-change checks. No paid API fallback.
5. Google remains separately pending. Do not start genuine Google consent/API reads based on ChatGPT approval. Production signing, provider eligibility/license review and a real signed update host/key are independent release gates; no placeholder update URL or unsigned publication is part of acceptance.

## Observation record

Each row needs: case/run ID; artifact version/hash; category; sender/receiver OS and app version; capture source/backend; monitor/DPI/devices; protection off result; configured UI/native value where measured; protection on result; transition exposure; steps/expected/actual; elapsed/CPU/memory/queues; tester/time; evidence path; PASS/FAIL/PENDING/BLOCKED and reason. A scope that cannot be selected or recorded is not a generic compatibility pass. Open a reproducible defect only after ruling out fixture/source/permission/setup mistakes; retain failure evidence and rerun the exact scenario after a fix.
